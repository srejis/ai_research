## 3. 공식 데이터셋 선택

### 3.1 출처

사용할 데이터는 다음 Moving AI Lab 공식 자료다.

- https://movingai.com/benchmarks/
- https://movingai.com/benchmarks/grids.html
- https://movingai.com/benchmarks/mapf/index.html
- https://movingai.com/benchmarks/formats.html

32×32 크기의 실제 공개 지도부터 시작한다.

우선 선택할 공식 MAPF 지도:

- `maze-32-32-2.map`
- `maze-32-32-4.map`
- `random-32-32-10.map`
- `random-32-32-20.map`
- `room-32-32-4.map`

각 지도에 대응하는 공개 even/random 시나리오를 사용한다.

이 파일들은 Moving AI가 공개한 자료에서 직접 다운로드한다.

**기존 EXP003처럼 새로운 무작위 미로를 만들어 데이터 수를 채우지 않는다.**

### 3.2 MAPF 자료의 사용 범위

선택한 32×32 자료는 원래 여러 에이전트의 경로를 계획하는 MAPF 벤치마크다.

이번 연구에서는 개별 에이전트의 시작점·목적지 쌍을 추출하여 단일 에이전트 경로 탐색 문제로 사용한다.

따라서 보고서에는 다음과 같이 명시한다.

> Moving AI 공식 MAPF 지도·시나리오에서 추출한 단일 에이전트 경로 탐색 평가

이것을 Moving AI가 공식적으로 제공한 단일 에이전트 모델 평가 점수와 동일하다고 주장하지 않는다.

MAPF 시나리오가 공식 2D 단일 에이전트 `.scen` 파일과 같은 구조 또는 최적 경로 비용 필드를 가진다고 가정하지 않는다.

다운로드 후 실제 파일 포맷을 먼저 검사한다.

포맷이 다르면 정확한 형식에 맞춰 파서를 구현하고 원본 구조를 문서화한다. 변환 불가능하거나 파일이 누락되면 오류를 명시하고 중단한다. 다른 자체 생성 데이터로 조용히 대체하지 않는다.

### 3.3 원본 보존과 검증

모든 파일에 대해 다음을 기록한다.

- 실제 원본 다운로드 URL
- 파일명과 출처
- 다운로드 시점
- 원본 SHA-256
- 원본 지도 크기
- 원본 시나리오 개수
- 파싱 성공·실패 건수
- 사용한 이동 규칙
- 최종 채택된 문제 개수

주의할 점은 `.map` 파일 내부 문자 `G`가 통행 가능한 지형을 뜻할 수 있고 `S`도 지형 문자라는 사실이다.

이 문자들을 시작점이나 목적지로 해석해서는 안 된다.

**모델의 시작점 S와 목적지 G는 시나리오에 기록된 좌표만 사용한다.**

## 4. 경로 탐색 문제 정의

각 데이터 항목은 다음으로 구성한다.

```text
공식 미로 지도
공식 시작 좌표 S
공식 목표 좌표 G
```

AI는 이 세 정보를 모두 입력받는다.

AI가 해결할 문제는 다음과 같다.

**벽을 통과하지 않고 S에서 G까지 실제로 이동할 수 있는 경로를 찾는다.**

이전 연구의 'G에서 도달할 수 있는 모든 칸을 색칠하기'와는 다른 작업이다.

이번에는 경로를 따라 실제로 이동해 목적지에 도착했는지가 성공 기준이다.

### 이동 규칙

최초 32×32 MAPF 유래 문제는 4방향 이동으로 명시적으로 정의한다.

- 위
- 아래
- 왼쪽
- 오른쪽

각 합법 이동의 비용은 1이다.

대각선 이동은 허용하지 않는다.

이는 단일 에이전트 파생 평가를 위한 명시적인 규칙이다. 8방향 대각 이동을 사용하는 별도의 Moving AI 2D 단일 에이전트 시나리오 최적 길이와 직접 비교하지 않는다.

공식 시나리오에 이동 규칙 또는 최적 비용이 정의되어 있다면, 이를 별도로 읽어 원본 벤치마크 정의와 이번 파생 평가 정의의 차이를 보고한다.

## 5. 정답 경로 생성 및 검증

공식 데이터에는 지도와 시작·목적지 정보가 있지만, 사용하는 MAPF 자료에 개별 에이전트의 최적 길이가 반드시 기록되어 있다고 가정하지 않는다.

따라서 정답 최단 경로 길이는 선택한 4방향 이동 규칙에 따라 독립적인 BFS로 계산한다.

또한 별도의 Dijkstra 구현으로 결과를 교차 검증한다.

BFS/Dijkstra는 정답과 학습 목표 생성 및 결과 평가용이다.

**모델 추론 과정에 BFS, A*, Dijkstra를 호출해 답을 완성하는 기능을 넣지 않는다.**

정답은 유일한 경로 하나가 아닐 수 있다.

복수의 동일한 최단 경로가 있다면 어느 경로든 유효한 정답으로 인정한다.

학습 목적으로 목적지 G까지의 최단 거리 지도(distance-to-go field)를 생성할 수 있다.

이 지도는 각 통행 가능 칸에서 G까지 이동하는 데 필요한 최소 비용을 나타낸다.

거리 지도는 최종 경로를 만드는 데 활용할 수 있는 감독 정보이며, 모델 실행 중 정답 지도를 직접 입력하는 방식은 금지한다.

## 6. 데이터 유효성 필터

공식 시나리오의 각 문제를 다음 기준으로 검증한다.

- S와 G가 실제 지도 범위 안에 있는가?
- 두 위치가 통행 가능한 셀인가?
- S와 G가 서로 다른가?
- S에서 G까지 실제 경로가 존재하는가?
- 경로가 너무 짧지는 않은가?
- 동일한 지도·S·G 조합이 반복되지 않는가?
- 좌표계가 뒤집히거나 x/y가 바뀌지 않았는가?

이번 연구에서 매우 짧은 경로가 문제였으므로 초기 필터는 **4방향 최단 거리 최소 12칸**으로 한다.

이 조건을 통과하지 못한 시나리오는 연구용 부분집합에서 제외할 수 있지만, 공식 원본은 그대로 보존한다.

제외 사유와 개수를 반드시 기록한다.

데이터가 부족하다고 필터를 조용히 완화하지 않는다.

학습·검증·테스트에 같은 S/G 문제가 중복 포함되지 않도록 검사한다.

### 중요: 지도 암기 방지

공식 32×32 지도는 지도 종류와 개수가 제한되어 있다.

같은 지도에서 출발·목적지 위치만 바꾼 데이터로 학습·테스트하면, 모델이 그 지도의 연결 구조를 외울 가능성이 있다.

따라서 두 평가를 분리한다.

1. **동일 지도 내 새로운 S/G 문제:** 이미 관찰한 지도에서 새로운 경로를 찾는 능력
2. **학습에서 제외한 지도 평가:** 처음 보는 지도 구조에 대한 일반화

두 번째 평가는 실제 보유 지도 수가 적어 지도 계열이나 분포 차이의 영향을 받을 수 있음을 명시한다.

지도 단위 평가가 가능하지 않은 경우 일반화 성공을 주장하지 않는다.

## 7. 난이도 구분

복잡도별 비교를 수행한다.

난이도는 공식 지도 크기만으로 정하지 않는다.

최단 경로 길이를 주요 기준으로 하고, 가능하면 다음 속성도 분석한다.

- 벽 밀도
- 분기 수
- 막다른 길 수
- 시작점과 목적지 사이의 Manhattan 거리
- 실제 최단 경로 / Manhattan 거리의 비율
- 우회해야 하는 구간
- 직선적인 구간과 복잡한 꺾임의 수

최단 거리 구간은 실제 공식 시나리오의 분포를 확인한 뒤 훈련 데이터 기준으로 고정한다.

난이도 구간에 존재하는 샘플 수를 함께 기록한다.

특정 구간이 비어 있으면 결과를 임의 보간하지 않는다.

## 8. 모델의 출력 방식

이전 EXP003에서는 AI가 최종 도달 가능 영역을 직접 예측했다.

이번에는 **목적지까지 가는 경로를 실제로 구성할 수 있도록** 출력 목표를 변경한다.

초기 구현은 목적지까지의 거리 지도 예측 방식으로 구성한다.

모델 출력은 32×32, 총 1,024개 셀에 대한 예상 거리 점수다.

각 셀의 정답은 독립 계산한 목적지까지의 최단 거리다.

학습에서는 거리값을 고정된 규칙으로 정규화하여 수치 범위를 안정적으로 유지한다. 정규화 및 역변환 식을 설정과 보고서에 기록한다.

도달할 수 없는 셀과 벽은 명시적으로 구분하고, 손실 마스킹 및 처리 정책을 기록한다.

전체 지도에 대해 동일한 거리 지도 감독을 A/B/C/D에 적용한다.

### 예측 경로 생성

모델이 예측한 거리 점수를 사용하여 S에서 경로를 구성한다.

1. S에서 시작한다.
2. 지도상 이동 가능한 이웃 칸을 조사한다.
3. 모델의 거리 예측값이 현재 칸보다 낮은 이웃 중 가장 작은 값을 가진 칸으로 이동한다.
4. G에 도착하면 성공이다.
5. 더 낮은 합법적 이웃이 없거나, 이미 방문한 칸을 다시 방문하려 하거나, 정해진 이동 제한을 초과하면 실패로 기록한다.

이 과정은 모델이 예측한 점수를 행동으로 변환하는 공통 디코더이며, 정답 거리장이나 별도의 그래프 탐색으로 실패를 복구하지 않는다.

A/B/C/D 모두 정확히 같은 경로 디코더를 사용한다.

지도에서 벽과 합법 이동을 확인하는 것은 허용하되, 정답 경로를 탐색하는 기능을 넣지 않는다.

또한 모델이 법적으로 불가능한 이동을 가장 높게 평가한 빈도도 별도 지표로 기록한다.

## 9. 공유 가중치 반복 모델

이번에도 기본은 MLP로 유지한다.

32×32 지도를 동일한 크기의 벡터로 변환한다.

입력에는 다음을 반드시 포함한다.

- 벽 지도 W
- 시작 위치 S
- 목적지 위치 G
- 현재 반복 상태 R

반복 계산:

\[
R_{k+1}=F_\theta(W,S,G,R_k)
\]

원본 W/S/G는 모든 반복에서 동일하게 유지한다.

반복 중 상태 R만 갱신한다.

초기 R0는 구현 시 정한 고정 초기 거리 점수로 설정하고, 이 초기 상태와 정규화 방식을 반드시 기록한다.

초기 8회 반복을 기본값으로 한다.

같은 MLP 인스턴스와 동일한 가중치를 매번 호출하며, 스텝별 별도 가중치를 만들지 않는다.

반복 코어를 학습할 때는 실제 예측 R을 다음 입력에 사용하고 전체 BPTT로 학습한다.

이번에는 모든 단계에서 최종 목적지까지의 거리 지도를 목표로 하는 동일 과제를 사용한다. 마지막 단계 손실과 전체 단계 손실의 가중치를 명시적으로 기록한다.

EXP003의 단계별 BFS 영역 감독과는 목표가 달라졌으므로 결과를 직접 같은 의미로 비교하지 않는다.

## 10. 비교 모델

### A — 단일 MLP

입력 지도와 S/G를 한 번에 처리해 거리 지도를 예측한다.

동일한 공통 경로 디코더로 S→G 경로를 생성한다.

기본 단일 MLP와 별도로, 파라미터 수 및 forward FLOPs를 대응시킨 대형 기준선도 준비한다.

### B — 반복 MLP

같은 가중치 코어를 8회 반복한다.

마지막 R8을 거리 지도 예측으로 사용한다.

출력 MLP는 없다.

### C — 반복 MLP + 마지막 결과 출력 MLP

B와 동일한 학습 완료 반복 코어를 사용한다.

반복 코어를 동결한 상태에서 별도의 비순환 출력 MLP를 학습한다.

출력 MLP에는 원본 문제와 마지막 R8을 사용한다.

D와 입력 차원·출력 MLP 구조·가중치 수를 맞추기 위해 R8을 과거 기록 슬롯 수만큼 복제한다.

### D — 반복 MLP + 과거 전체 기록 출력 MLP

C와 완전히 동일한 반복 코어를 사용한다.

같은 출력 MLP 구조를 유지하지만 입력에 실제 R1~R8을 제공한다.

즉, C와 D의 차이는 마지막 결과 복제냐 실제 과거 중간 결과냐로 제한한다.

D의 출력은 반복 코어로 다시 들어가지 않는다.

### E — 원본 문제만 사용하는 출력 MLP

C/D와 같은 출력 헤드 구조를 사용하되 기록 슬롯은 0으로 채운다.

출력 MLP가 반복 기록 없이 직접 문제를 푸는 능력을 비교한다.

### 공정성

- A/B/C/D/E에 같은 지도와 S/G 입력을 제공한다.
- C/D는 같은 반복 코어의 체크포인트를 공유한다.
- C/D의 출력 헤드 구조, 초기화, 배치 순서를 대응시킨다.
- 코어는 먼저 학습한 뒤 동결한다.
- 헤드만 학습한 결과와 코어까지 다시 학습하는 End-to-End 방식은 섞지 않는다.
- 코어에 추가 감독을 제공하는 비용과 효과를 기록한다.
- 동일 파라미터 수, 동일 추정 FLOPs, 실제 학습 시간 예산은 서로 다른 비교 조건으로 구분한다.

## 11. 학습 설정

기존 `research` Conda 환경을 사용한다.

기본 설정 후보:

```text
Environment: D:\anaconda3\envs\research
Device: CUDA
Precision: FP32

Seeds: 42, 123, 2026
Core recurrence steps: 8

Optimizer: AdamW
Learning rate: 0.001
Batch size: 128

Core epochs: 80
Head epochs: 80
Baseline epochs: 80
```

이 설정은 초기 기준이며, 공식 데이터 수와 유효 경로 분포를 감사한 후 실제 채택값을 설정 파일에 확정한다.

기존 EXP003 결과를 재현하기 위해 데이터 수를 강제로 12,288개까지 맞추지 않는다.

공식 데이터에서 실제 얻은 적격 시나리오의 개수를 우선한다.

데이터가 지나치게 부족하면 명확하게 보고하고, 공식 지도·시나리오의 범위를 넓히는 방법을 제시한다.

작업 중 새 시나리오를 자체 생성하여 공식 데이터처럼 섞지 않는다.

## 12. 성능 평가 — 최우선 지표

기존 IoU 대신 **실제 경로 탐색 성공률**을 주요 성능으로 한다.

반드시 다음 지표를 기록한다.

1. **경로 탐색 성공률:** S에서 G에 도착한 문제 비율
2. **경로 합법성:** 벽 통과·범위 이탈·불법 이동 여부
3. **최적 경로 대비 비용:** 실제 경로 길이 / BFS 최적 길이
4. **최적 경로 발견률:** 비용이 최적 경로와 일치하는 성공 사례의 비율
5. **루프·정체 실패율:** 순환, 지역 최소점, 최대 이동 제한 등의 실패 유형
6. **거리 지도 예측 오차:** 예측값과 Dijkstra/BFS 거리장 차이
7. **추론 비용:** FLOPs, GPU 지연 시간, 메모리
8. **학습 비용:** 시간, optimizer step, 전체 모델 호출 수

경로를 찾지 못한 실패 사례는 최적 비용 비율의 평균에서 단순 제외하면 선택 편향이 생긴다.

따라서 성공률과 성공한 사례의 비용 비율을 별도로 보고하고, 전체 과제에 대한 성공·최적성 종합 지표도 제공한다.

또한 난이도별·지도별·S/G 거리별 결과를 구분한다.

## 13. 과거 기록 통합의 효과 검증

D가 C보다 우수한 경우 그 차이를 명확하게 검증한다.

- R1~R8 기록을 전부 제거
- 마지막 R8을 모든 슬롯에 복제
- 기록의 시간 순서를 역순으로 변경
- 기록의 시간 순서를 무작위로 섞기
- 특정 시점 R1~R8을 각각 제거
- 다른 공식 시나리오에서 나온 기록으로 대체

학습 완료한 D를 변경하지 않고 입력만 교란해 결과를 기록한다.

다만 이런 교란은 학습 분포에서 벗어날 수 있으므로 성능 하락만으로 과거 기록이 근본적인 해결 능력을 제공했다고 주장하지 않는다.

**가장 직접적인 검증은 별도로 정상 학습한 C와 D의 동일 테스트 결과 비교다.**

이전 EXP003처럼 기록 교란에 극도로 민감하지만 C와 비슷한 정확도라면 과거 전체 기록의 추가 이득은 여전히 미확정이다.

D 모델에는 R1~R8의 거리 예측 변화와 최종 출력 MLP의 거리 지도를 함께 시각화한다.

**S가 실제로 G에 갈 수 있는 문제인지 시각화 전에 검증하고, S와 G를 공식 좌표 그대로 표시한다.**

## 15. 검증 절차

본실험 전 `--smoke`로 파이프라인을 검증한다.

최소 검증 항목:

- 시작점과 목적지의 연결성 검사
- 12칸 이상 최단 거리 필터 검증

- 정답 경로가 실제로 벽을 통과하지 않는지 검사
- 경로 디코더가 별도 그래프 탐색으로 정답을 복구하지 않는지 검사
- Oracle 거리 지도를 넣었을 때 경로 디코더가 합법적인 최적 경로를 복원하는지 검사
- 모델에 S와 G가 모두 실제 입력되는지 확인
- train/val/test 문제 중복 검사
- 동결된 코어의 가중치 불변 검사
- C와 D의 출력 MLP 초기화 대응 검사
- 체크포인트 저장·복원 검증
- 기존 H001 및 H002 EXP001~003 파일·체크포인트·결과 보존 검증

**공식 데이터 원본과 우리가 모델에 전달한 문제, 시각화된 문제, 정답 경로가 전부 동일한지 반드시 교차 검증한다.**

이미지 렌더링 단계에서 S/G가 바뀌거나 벽 구조가 왜곡되지 않도록 검사한다.

성공률을 높이기 위해 모델 출력 뒤에 BFS나 A*를 추가하는 등의 우회 처리는 금지한다.

기존 합성 미로 실험 결과와 새로운 경로 탐색 실험의 정확도는 서로 다른 평가이므로 같은 지표로 합쳐 비교하지 않는다.
