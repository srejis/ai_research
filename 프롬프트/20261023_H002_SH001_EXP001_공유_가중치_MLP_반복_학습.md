# H002 / SH001 / EXP001 — 공유 가중치 MLP 반복 학습 실험 구현 지시

## 1. 작업 목적

저장소: https://github.com/srejis/ai_research

이번 작업은 동일한 신경망을 반복 실행했을 때 계산 단계가 추가되면서 결과가 실제로 개선될 수 있는지 확인하는 첫 실험이다.

우리가 궁극적으로 연구하려는 모델은 외부 입력이 없어도 자신의 내부 결과를 다시 입력받아 사고를 지속하고, 새 입력이 들어오면 기존 사고 상태와 새 정보를 결합해 판단을 갱신하는 모델이다.

그러나 처음부터 영상 인식, 외부 입력 결합, 지속 실행까지 구현하면 실험 결과의 원인을 구분하기 어렵다.

따라서 이번에는 **동일한 MLP, 동일한 가중치, 동일한 입력·출력 차원으로 반복 추론을 수행하고, 학습 과정에도 반복 계산을 포함하는 것**만 검증한다.

핵심 연구 질문:

> 동일한 가중치를 사용하는 MLP를 반복 학습시키면, 반복 횟수가 증가하면서 정답 오차가 감소하는 현상을 확인할 수 있는가?

반복이 개선을 보장한다고 전제해서는 안 된다. 개선, 정체, 진동, 발산 모두 유효한 실험 결과다.

## 3. 모델 구조

기본 MLP:

```text
Input 64
   ↓
Linear 64 → 128
   ↓
ReLU
   ↓
Linear 128 → 64
   ↓
Sigmoid
   ↓
Output 64
```

수식:

\[
h_{k+1}=f_\theta(h_k)
\]

- 최초 상태 `h0`는 입력 패턴이다.
- 각 스텝의 출력은 다음 스텝의 입력이다.
- 모든 반복에서 동일한 모델 인스턴스와 동일한 파라미터를 사용한다.
- 반복 단계별 별도 Linear 레이어를 생성하지 않는다.
- 모델은 기본적으로 16,576개의 학습 가능한 파라미터를 가진다.
- 최초 구현에서는 Residual Connection, Attention, Normalization, 외부 메모리를 추가하지 않는다.

모델은 반복 횟수를 인자로 받아 각 단계의 64차원 출력을 반환할 수 있어야 한다.

추론 도중 가중치가 변경되어서는 안 된다.

## 4. 데이터셋

최초 실험은 **8×8 이진 패턴 복원**으로 진행한다.

- 원본 패턴: 64차원 이진 벡터
- 손상된 입력: 원본 픽셀 일부를 반전시킨 벡터
- 정답: 손상 이전 원본 벡터
- 기본 오류 확률: 15%
- 초기 학습 4,096개, 검증 1,024개, 테스트 1,024개
- seed 42를 기준으로 데이터 생성

중요한 조건:

완전히 독립적인 무작위 64비트 벡터를 만들고 일부 비트만 손상시키면, 손상 여부를 알아낼 구조적 정보가 부족할 수 있다.

따라서 원본 패턴은 재현 가능한 구조적 생성 규칙을 사용해야 한다. 예를 들어 직선, 직사각형, 대칭 도형 등의 조합을 사용한다.

학습·검증·테스트 샘플은 중복되지 않도록 분리한다. 원본 패턴과 노이즈의 생성 시드를 기록한다.

복원 문제가 지나치게 쉬운지 또는 정답 복원이 본질적으로 모호한지도 분석한다.

## 5. 비교 모델

세 가지 조건을 학습한다.

### A. Single-step MLP

MLP를 단 한 번 실행하도록 학습한다.

\[
L_A=BCE(h_1,y)
\]

반복하지 않는 일반적인 MLP의 기준 성능이다.

다만 학습 완료 후 동일 가중치를 추가 반복하여 어떤 변화가 발생하는지도 별도로 평가한다.

### B. Recurrent MLP — Final Loss

동일한 MLP를 8회 반복한다.

\[
L_B=BCE(h_8,y)
\]

마지막 결과만 정답과 비교하고, 8개 반복 단계를 모두 통과하도록 역전파한다.

### C. Recurrent MLP — All-Step Loss

동일한 MLP를 8회 반복한다.

\[
L_C=\frac{1}{8}\sum_{k=1}^{8}BCE(h_k,y)
\]

매 반복 결과에 손실을 적용한다.

이는 매 단계가 유효한 출력을 생성하도록 유도하는 방식이다. 다만 반복할수록 오차가 감소하도록 보장하는 손실 함수는 아니다.

### 공정한 비교 조건

- 세 모델의 구조 및 파라미터 수를 동일하게 유지한다.
- 같은 학습·검증·테스트 데이터를 사용한다.
- 대응 seed에서는 초기 가중치를 동일하게 설정한다.
- 동일한 optimizer와 batch size를 사용한다.
- 학습 epoch, 실제 optimizer step 수와 학습 시간을 모두 기록한다.
- 반복 모델이 학습 중 더 많은 연산을 수행한다는 점을 반드시 기록한다.
- 학습 반복 횟수가 8회라는 이유만으로 특정 결과를 우수하다고 평가하지 않는다.

## 6. 학습 설정

초기값:

```text
Optimizer: AdamW
Learning rate: 0.001
Batch size: 128
Epochs: 80
Seeds: 42, 123, 2026
Precision: FP32
Training repeat steps: 8
Evaluation repeat steps: 1, 2, 4, 8, 16, 32
```

GPU가 사용 가능하면 CUDA에서 실행한다. 장치·PyTorch·CUDA 버전 및 GPU 모델을 기록한다.

`PYTHONNOUSERSITE=1`을 사용해 기존 환경 외부의 사용자 패키지 혼입을 방지한다.

학습은 전체 반복 계산을 포함한 BPTT를 사용한다.

발산, NaN, gradient 폭증, 손실 정체가 나타나면 자동으로 결과를 조작하거나 학습 알고리즘을 교체하지 않는다. 원래 조건의 실패를 보존한다.

필요하면 원래 실행과 구분되는 별도 실험에서 안정화 조치를 시도할 수 있다.

## 7. 평가 방법

학습 종료 후 **1, 2, 4, 8, 16, 32회** 반복한 결과를 모두 평가한다.

반드시 학습에 사용하지 않은 테스트 데이터에서 측정한다.

기록할 지표:

1. 반복별 BCE 손실
2. 반복별 픽셀 오류율 및 복원 정확도
3. 이전 반복 대비 개선 또는 악화된 샘플 비율
4. 반복 상태의 평균·최대 변화량
5. NaN, 발산 및 진동 여부
6. 반복별 실제 GPU 추론 지연 시간
7. 모델별 총 학습 시간과 peak GPU 메모리

GPU 추론 시간은 warm-up 후 CUDA 동기화를 포함해 측정한다. 입력 데이터 전송을 포함한 종단 간 시간과 모델 실행 시간은 구분한다.

최종 반복 결과만 측정하지 말고 매 반복의 결과를 개별적으로 보존한다.

가능하면 1~32회 전 구간도 측정해, 선택된 6개 지점 사이에 숨은 진동이 있는지 검토한다.

## 8. 시각화

최소한 아래 결과를 생성한다.

- 반복 횟수에 따른 픽셀 오류율 그래프
- 반복 횟수에 따른 BCE 그래프
- 반복 횟수에 따른 상태 변화량 그래프
- 원본 패턴 / 손상된 입력 / 반복 1·2·4·8·16·32회 복원 이미지
- 세 학습 방식의 비교표
- seed별 결과 및 평균·표준편차

그래프에 실험 조건, 단위, 비교 모델을 명시한다.

복원 이미지는 같은 샘플을 비교해야 한다. 좋은 사례만 선택하지 말고, 개선·정체·악화 사례를 각각 포함한다.

## 9. 결과 보존 및 검증

실험 결과는 기존 저장소의 규칙처럼 아래에 보존한다.

```text
EXP001_recurrent_mlp/
├── checkpoints/<run_id>/
└── results/<run_id>/
```

각 실행은 고유한 `run_id`를 가진다. 기존 실행을 덮어쓰지 않는다.

각 실행에 학습 설정, 모델 체크포인트, 환경 정보, 난수 시드, 단계별 수치, 그래프, 보고서를 보존한다.

검증 스크립트는 다음을 확인해야 한다.

- 입력과 출력 차원이 정확히 64인지
- 반복마다 동일한 모델 파라미터를 재사용하는지
- 8단계 손실에서 1단계부터 8단계까지 gradient가 전달되는지
- 저장 체크포인트를 다시 읽고 평가 결과를 재현할 수 있는지
- 테스트 데이터와 학습 데이터가 섞이지 않았는지
- 기존 H001 파일 및 결과가 변경되지 않았는지

## 10. 결과 해석 시 주의사항

이번 실험은 반복 추론의 가능성을 검증하기 위한 것이며 특정 가설을 입증하도록 결과를 유도해서는 안 된다.

특히 다음을 구분한다.

- **반복 횟수 증가에 따른 개선:** 동일한 모델의 결과가 단계가 진행될수록 정답에 가까워졌는가?
- **반복 학습 자체의 효과:** 8회 반복하도록 학습한 모델이 일반 MLP와 다른 결과를 보였는가?
- **연산 효율:** 반복하는 편이 같은 계산 예산의 다른 모델보다 유리한가?
- **장기 안정성:** 학습 범위인 8회를 넘어 16·32회 반복해도 성능이 유지되는가?

8회에서 결과가 좋더라도 1회보다 나쁘면 '반복할수록 개선됐다'고 판단해서는 안 된다.

반복 모델의 성능이 단일 모델보다 좋더라도, 학습 또는 추론 계산량 차이 때문일 가능성을 분리해야 한다.

이진 패턴 복원에 성공해도 로봇의 지속적인 사고 능력이 검증된 것은 아니다.

가능하면 학습 완료 후 검증과 그래프 생성을 자동 수행한다.

실험 결과 보고에는 반드시 다음 판단을 포함한다.

**"동일한 가중치를 반복 학습하고 반복 추론했을 때, 실제 정답 품질이 개선되었는가?"**

개선되지 않았다면 단순 학습 부족, 수렴 상태, 진동, 정보 손실, 학습 목표의 부적합성 중 무엇이 관찰되었는지 구분하여 설명한다. 관측만으로 원인을 확정할 수 없으면 미확정으로 표시한다.

마지막으로 코드 구현 내역, 실행 명령, 생성된 파일, 실제 측정 결과, 검증 결과, 알려진 한계, 다음 실험 후보를 한국어로 보고한다.

커밋 메시지 한 개도 추천한다.

이번 작업에서는 구현과 실험 수행에 집중하며, 사용자의 기존 H001 연구 산출물이나 GitHub 이력을 정리하거나 변경하는 부수 작업은 진행하지 않는다.
