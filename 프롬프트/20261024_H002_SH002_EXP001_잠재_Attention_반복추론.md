## 1. 작업 목적과 배경

대상 저장소: https://github.com/srejis/ai_research

이번 작업은 새로운 내부 사고 구조를 실제 학습·평가하는 첫 실험이다.

기존 H002/SH001의 EXP001~004에서는 공유 가중치 반복의 유용성을 검토했지만, 반복 상태가 완성된 정답과 유사한 형태로 구성되거나 매 단계 정답을 직접 감독받는 문제가 있었다.

특히 EXP004는 공식 Moving AI 미로 자료를 사용해 실제 S→G 경로 탐색을 평가했지만, 모든 반복에서 최종 거리장을 지도했다. 그 결과 동일 지도에서도 최고 모델 D의 성공률은 약 5.01%, 미관찰 지도에서는 약 0.0032%였다. 거리장 출력에서 국소적으로 더 낮은 값을 찾지 못해 정체하는 문제가 관측되었다.

새 모델은 다음의 사용자 의도를 구현해야 한다.

1. 모델이 정답 자체가 아닌 **내부 사고 상태**를 반복적으로 갱신한다.
2. 각 반복에서 Q/K/V Attention을 사용해 현재 필요한 원본 입력과 과거 기록을 읽는다.
3. 내부 사고 상태에 중간 정답이나 역할을 강제하지 않는다.
4. 정답 손실은 최종 출력에서만 계산한다.
5. 정확도를 가장 우선으로 하고, 충분히 학습한 후 더 적게 생각하면서 정확도를 유지하는 종료 정책을 학습한다.
6. 모델이 현재 문제의 사고를 끝낼지 결정하되, 최대 반복 횟수는 안전장치로 둔다.

이번 실험은 이 구조가 실제로 학습되고 경로 탐색에 도움이 되는지 검증한다.

**반드시 반복해야만 풀 수 있는 인위적인 문제를 만드는 것은 목적이 아니다.**

첫 단계에서 올바른 답을 찾을 수 있다면 그것 역시 허용한다.

## 4. 모델 v0.1 전체 구조

모델은 다음 모듈로 구성한다.

```text
공식 미로 문제 (W, S, G)
          │
          ▼
    입력 인코더
          │
          ▼
   원본 입력 메모리 X
          │
          │      초기 잠재 상태 H0
          │              │
          │              ▼
          ├──────► 공유 사고 코어 ◄───── 과거 잠재 기록
          │         Cross-Attention
          │         Self-Attention
          │         MLP
          │              │
          │              ▼
          │         다음 상태 Ht
          │              │
          │       기록 메모리에 추가
          │              │
          │              ▼
          │         종료 판단부
          │           /      \
          │        계속      완료
          │         │          │
          │         └─반복     ▼
          │                 출력 헤드
          │                     │
          ▼                     ▼
    위치·국소 정보       1024×4 이동 방향 점수
                               │
                               ▼
                        S→G 실제 경로 평가
```

출력 헤드가 만든 답은 반복 코어에 재입력하지 않는다.

문제 풀이 중간에 생성된 잠재 상태의 내용은 사람이 특정 의미를 지정하지 않는다.

## 5. 입력 인코더

공식 지도는 32×32다.

모든 칸은 독립적인 입력 토큰으로 표현한다.

각 토큰에는 다음 원본 정보만 포함한다.

- 벽 여부
- 시작점 S 여부
- 목적지 G 여부
- 행 좌표
- 열 좌표

32×32 전체를 다음 모양으로 변환한다.

`X: [batch, 1024, 128]`

초기 모델에서는 칸별 공유 Linear 또는 작은 MLP를 사용한다.

행·열 위치는 2차원 위치 부호화로 구분한다.

인코더가 처음부터 전역 Self-Attention으로 미로를 해결하지 않도록 한다. 입력 인코더의 목적은 원본 문제를 읽을 수 있는 표현으로 바꾸는 것이다.

X는 한 문제를 처리하는 동안 읽기 전용이다.

단, 입력 인코더의 가중치는 문제 해결 학습에서 최종 손실에 따라 학습되어야 한다.

BFS 거리, 최단 방향 정답, 도달 가능 마스크를 모델 입력에 포함하지 않는다.

## 6. 내부 잠재 작업 공간

초기 잠재 상태는 다음 형태다.

`H0: [batch, 16, 128]`

16개의 서로 구별되는 학습 가능한 초기 잠재 벡터를 사용한다.

각 벡터는 모델의 내부 작업 공간이다.

특정 벡터에 경로 탐색, 검증, 장애물 분석 등의 역할을 미리 할당하지 않는다.

한 번의 반복이 끝나면 다음 잠재 상태를 얻는다.

`H1, H2, ... , H16`

모든 잠재 상태는 같은 형태를 유지한다.

잠재 상태 자체에는 다음을 금지한다.

- 정답 거리장 형태 강제
- 0~1 도달 가능 마스크 형태 강제
- 단계별 BFS 정답 손실
- 단계별 최종 방향 지도 손실
- 내부 잠재 벡터를 특정 의미에 대응시키는 수동 규칙

반복 상태는 자유로운 학습 표현이어야 한다.

## 7. Q/K/V 기반 사고 코어

한 번의 사고 코어는 다음 세 연산으로 구성한다.

### 7.1 Cross-Attention

현재 잠재 상태에서 Q를 생성한다.

원본 입력과 과거 기록에서 K/V를 생성한다.

```text
Q: 현재 Ht
K: 원본 X + 과거 H 기록
V: 원본 X + 과거 H 기록
```

최초 반복에서는 과거 기록이 없으므로 원본 X만 참조한다.

두 번째 반복 이후에는 이전에 만들어진 상태들도 참조할 수 있어야 한다.

기록 시점, 잠재 슬롯 구분, 원본 입력인지 기록인지 구분하는 정보를 K/V 표현에 포함한다.

같은 가중치를 반복적으로 사용하되 각 반복의 Q/K/V 입력 내용은 달라질 수 있다.

### 7.2 잠재 상태 Self-Attention

현재 16개 작업 벡터 사이에 Self-Attention을 수행한다.

각 작업 벡터가 다른 작업 벡터에서 계산된 내용을 참조할 수 있게 한다.

### 7.3 MLP 상태 갱신

Self-Attention 결과를 MLP로 처리한다.

초기 구조:

- 입력 폭 128
- 은닉 폭 512
- 출력 폭 128
- 활성화 GELU
- Pre-LayerNorm
- Residual connection

Attention 설정:

- Hidden dimension: 128
- Attention heads: 4
- Head dimension: 32

Cross-Attention, Self-Attention, MLP는 서로 별도 파라미터를 가지지만, 이 세 모듈을 묶은 **동일한 사고 코어를 모든 반복에서 재사용한다.**

반복마다 서로 다른 블록 인스턴스를 생성하면 안 된다.

입력 메모리 X는 반복 중 갱신하지 않는다.

## 8. 과거 잠재 기록 메모리

각 사고 반복 이후 생성된 잠재 상태를 기록한다.

다음 반복에서 참조할 수 있는 기록은 지금까지 생성된 상태에 한정한다.

기본 최대 반복 수는 16회다.

따라서 최대 16개 상태 기록, 각 상태당 16개의 잠재 토큰을 저장할 수 있다.

**중요한 학습 규칙:** 문제 해결 학습 중 과거 상태를 임의로 `detach()`해서 최종 손실의 역전파 경로를 끊지 않는다.

기록 저장이 GPU 메모리 사용에 미치는 영향을 측정한다.

Cross-Attention 메모리 길이가 늘어날수록 계산량도 증가하므로, 모델이 단순히 가중치를 공유한다는 이유로 메모리 또는 연산량이 일정하다고 주장하지 않는다.

기본 버전에서는 기록 압축이나 삭제 정책을 추가하지 않는다.

## 9. 최종 출력 헤드

최종 출력은 **각 통행 가능한 칸에서 목표점으로 이동하기 위한 네 방향 점수**다.

출력:

`[batch, 1024, 4]`

방향 순서는 위·아래·왼쪽·오른쪽으로 고정한다.

종료 시 마지막 잠재 상태 H_T에서 최종 답을 생성한다.

최종 헤드는 작은 Cross-Attention과 공유 MLP로 구성한다.

출력 쿼리는 각 셀의 좌표와 국소 W/S/G 정보에서 만들고, K/V는 마지막 잠재 상태 H_T에서 얻는다.

출력 쿼리가 원본의 국소 정보를 보는 것은 허용하지만, 별도의 거대한 전역 인코더가 원본 미로만으로 답을 계산하게 하지 않는다.

**초기 v0.1에서는 출력 헤드가 과거 전체 기록에 직접 접근하지 않는다.**

과거 기록을 활용하는 기능은 사고 코어 내부에 둔다.

전체 기록을 마지막 출력에도 다시 결합하는 구조는 별도 제거 실험 또는 후속 실험으로 구분한다.

최종 정책 로짓은 Softmax 전에 그대로 반환하고, 학습 손실에서 필요한 확률을 계산한다.

## 10. 최종 지도학습 목표

BFS/Dijkstra는 모델의 외부에서 정답 생성과 검증에만 사용한다.

독립 BFS로 각 칸에서 목표점 G까지의 최단 거리를 계산한다.

목표에 도달 가능한 비목표 통행 칸에서, 최단 거리를 정확히 1 줄이는 합법 방향들의 집합을 구한다.

복수의 방향이 동일한 최단 경로를 형성한다면 모두 정답으로 인정한다.

학습 목표는 다음과 같다.

**정답 방향 집합에 할당된 모델 확률의 합을 최대화한다.**

각 감독 셀 i에 대해:

\[
L_i=-\log \sum_{a\in A^*(i)}P(a\mid i)
\]

`A*(i)`는 현재 셀에서 선택할 수 있는 최적 이동 방향 집합이다.

실제 구현에서는 `logsumexp`와 `log_softmax`를 사용해 수치적으로 안정적으로 계산한다.

벽, 목표점 자체, 목표에 도달할 수 없는 빈칸은 방향 지도 손실에서 제외한다.

각 미로의 유효 감독 셀 평균을 계산한 뒤 배치 평균을 구한다. 따라서 열린 칸 수가 많은 미로가 자동으로 과도한 손실 가중치를 갖지 않도록 한다.

이 감독 마스크는 손실 계산 전용이며 모델 입력에는 전달하지 않는다.

모델이 벽 방향을 예측할 경우 실제 평가에서 실패할 수 있으므로, 초기 평가에서는 불법 방향 점수를 모델 출력에서 미리 제거하지 않는다.

**이 학습 손실은 마지막 정책 지도에 한 번만 적용한다.**

최초 v0.1 문제 해결 학습에서 내부 H1~H15에는 별도의 정답 손실을 적용하지 않는다.

## 11. 실제 경로 생성 및 평가

모델의 최종 출력 정책을 가지고 S에서 이동한다.

현재 칸의 네 방향 로짓 중 가장 높은 방향을 선택한다.

선택한 방향이 범위 밖이거나 벽이면 실패다.

다른 방향으로 자동 교체하거나 그래프 탐색으로 우회하면 안 된다.

합법적으로 이동했다면 다음 칸에서도 해당 칸의 정책 로짓을 읽는다.

G에 도착하면 성공이다.

다음 중 하나라도 발생하면 실패로 처리한다.

- 벽 충돌
- 지도 밖 이동
- 같은 셀 재방문
- 최대 이동 횟수 1,024 초과
- NaN/Inf 또는 정의되지 않은 예측

최적 경로의 복수 정답을 모두 인정한다.

모든 모델에서 동일한 경로 디코더를 사용한다.

Oracle 최적 방향 지도는 채택된 모든 S/G 문제에서 유효한 최적 경로를 완주해야 하며, 이 검증에 실패하면 본실험으로 진행하지 않는다.

모델 실패를 BFS/A*로 복구하는 기능은 절대로 추가하지 않는다.

## 12. 비교 모델

실험은 최소 다음 세 문제 해결 조건으로 구성한다.

### A — 별도로 학습한 1회 Attention 모델

동일한 입력 인코더, 동일한 잠재 상태 구조, 동일한 Attention+MLP 사고 블록과 출력 헤드를 사용한다.

사고 코어는 1회만 호출한다.

처음부터 1회에 최종 답을 맞히도록 독립적으로 학습한다.

16회 반복 모델을 1회에 잘라 평가한 결과를 이 기준선 대신 사용하면 안 된다.

### B — 공유 가중치 16회 반복 모델

동일한 사고 코어를 16회 반복한다.

원본 X와 과거 잠재 기록을 Cross-Attention으로 참조한다.

마지막 H16에서 한 번만 출력하고 정답을 감독한다.

이 모델을 향후 자율 종료 정책 학습의 기준으로 사용한다.

### C — 과거 기록을 읽지 않는 16회 반복 모델

B와 동일한 구조와 반복 횟수, 출력부를 사용한다.

차이는 Cross-Attention에서 과거 H 기록을 읽지 못하고 원본 X만 읽는다는 것이다.

초기부터 별도로 학습한다.

이를 통해 과거 기록 참조의 효과를 구분한다.

가능하면 파라미터 구조를 동일하게 유지하고, 실제 Attention 길이와 FLOPs 차이는 기록한다.

추가로 비공유 가중치를 갖는 동일 계산 예산의 깊은 Attention 모델을 별도 대조군으로 고려하되, 자원상 부담이 크다면 기본 세 모델의 결과를 먼저 보존한다.

## 13. 학습 1단계 — 문제 해결 능력

먼저 종료 정책을 사용하지 않는다.

B/C 모델은 항상 16회 사고 코어를 수행하고, A는 1회 수행한다.

최종 상태에서 출력 헤드를 단 한 번 호출한다.

최종 정책 지도 손실을 계산해 전체 모델을 학습한다.

역전파에는 입력 인코더, 초기 잠재 상태, 공유 사고 코어, 출력 헤드가 모두 참여한다.

BPTT를 통해 16회 전체의 계산 경로에 학습 신호가 전달되는지 검사한다.

중간 단계의 완성 정답을 가르치지 않는다.

기존 EXP004의 거리 지도 회귀 체크포인트를 새로운 정책 지도 모델에 무리하게 이식하지 않는다.

초기 학습 설정 후보:

- Seed: 42, 123, 2026
- Optimizer: AdamW
- Learning rate: 0.0003
- Weight decay: 0.01
- Batch size: 우선 16, GPU 사용량에 따라 명시적으로 조정
- Epoch 상한: 80
- Precision: FP32
- Gradient clipping: 1.0
- Device: CUDA
- 최대 사고 반복: 16

RTX 5090 32GB 환경을 기준으로 한다.

이 설정은 성능이 입증된 하이퍼파라미터가 아니라 최초 설정이다.

반복별 기록을 원본 그래프에 연결하는 Attention은 메모리 비용이 클 수 있으므로 전체 데이터 학습 전에 실제 최대 allocated memory, 최대 배치 크기, 배치 1개 학습 지연을 측정한다.

일반 PyTorch 다중 헤드 Attention 또는 SDPA 지원 구현을 우선 검토하되, 내부에서 완전한 Attention 행렬을 모두 보존하는 디버그 설정을 기본값으로 두지 않는다.

### 학습 가능성 사전 검사

본실험 전 고정된 소규모 학습 샘플에 대해 모델이 실제로 정책 손실을 낮추고 경로를 완주하도록 과적합할 수 있는지 검사한다.

작은 집합도 학습하지 못한다면 본실험의 실패를 단순히 미로가 어렵다고 해석하지 않는다.

이 경우 원인을 기록한다.

- 구현 오류
- Gradient 소실·폭발
- 기록 Attention 메모리 문제
- 출력 병목
- 경로 정책 손실과 완주율의 불일치
- 학습 설정 문제

작은 집합 과적합 실험은 본 데이터 일반화 성능과 분리해 보고한다.

검증 데이터를 이용한 체크포인트 선택은 미리 지정된 규칙으로 수행하고, 테스트 데이터는 모델 선택에 사용하지 않는다.

## 14. 학습 2단계 — 자율 종료 정책

이 단계는 B 모델의 문제 해결 학습이 완료되고 저장된 뒤 수행한다.

먼저 B의 인코더, 사고 코어, 출력 헤드를 동결한다.

각 반복의 잠재 상태를 읽는 작은 종료 헤드를 추가한다.

초기 구조:

`LayerNorm(128) → Linear(128,64) → GELU → Linear(64,1)`

입력은 현재 16개 잠재 벡터의 평균 풀링을 통해 생성한 128차원 요약이다.

이 출력에 sigmoid를 적용해 **현재 시점에서 종료를 선택할 조건부 확률**을 얻는다.

이 값은 정답 확률이 아니라 종료 선택 확률이다.

매 사고 반복 직후 종료를 평가한다.

최소 사고 횟수 1회, 최대 16회로 한다.

최대 16회에서 모델이 종료를 선택하지 않았다면 외부 상한에 의해 강제 종료한다.

정상 자율 종료와 상한 강제 종료를 구분해 기록한다.

### 학습 방법

초기 후보는 Bernoulli 종료 정책 + REINFORCE 방식이다.

훈련 중 각 문제의 종료 행동을 확률적으로 샘플링한다.

실제로 종료한 시점의 H_T에서 출력 헤드를 한 번 호출한다.

그 최종 답의 정책 손실, 실제 경로 완주 여부, 사고 반복 횟수를 측정한다.

종료하기 전의 각 잠재 상태에 중간 정답 손실을 부여하지 않는다.

종료 선택은 이산적이므로, REINFORCE의 로그 확률 경로와 action-independent baseline을 사용해 종료 정책을 학습한다.

정책에 전달하는 보상·비용은 정확한 부호를 사용하고, 종료 선택의 각 로그 확률 및 손실값을 기록한다.

학습 시 모델이 아무것도 배운 적 없는 이른 종료를 반복 선택하거나, 마지막 16회까지 항상 기다리는 경우가 발생할 수 있으므로 그 빈도를 관찰한다.

### 정확도 우선 정책

계산량 패널티는 초기 0에서 시작한다.

그다음 적은 양의 사고 비용을 부여한 정책 후보를 별도 설정으로 실험한다.

다만 최종 채택 기준은 단순히 가중 손실이 가장 작은 정책이 아니다.

**고정 16회 모델의 검증 성공률, SPL, 난이도별 품질이 허용 범위 내에서 유지되는 정책 중 평균 사고 횟수와 실제 지연이 낮은 정책을 선택한다.**

초기 기준은 관측된 정확도 저하를 허용하지 않는 방향으로 둔다. 검증 표본의 불확실성도 표시하며, 허용 범위가 정해지지 않았다면 임의로 정확도를 희생하는 기준을 확정하지 않는다.

이 기준을 만족하는 정책이 없다면 종료 정책이 성능 유지형 계산 절약에 성공하지 못했다고 보고한다.

기존 고정 16회 결과를 보존하고 종료 정책이 우수하다고 주장하지 않는다.

### 종료 정책과 코어의 공동 학습

코어와 출력 헤드가 16회 종료에서만 학습됐으므로, 중간 상태에서 유효한 답을 읽지 못할 수 있다.

종료 헤드만 학습한 결과가 모두 16회 종료를 선택한다고 해서 즉시 구조 전체의 실패로 확정하지 않는다.

필요한 경우 별도의 run에서 코어·출력 헤드·종료 헤드를 공동 미세조정한다.

이때도 **실제로 선택한 종료 시점의 마지막 답 한 번**에만 정답 손실을 적용한다.

종료 정책의 이산 행동 학습과 연속 신경망의 BPTT를 구분하여 구현한다.

기본 실험에서는 PonderNet 방식처럼 가능한 모든 종료 지점의 손실을 가중 평균하는 목적함수로 조용히 교체하지 않는다.

공동 학습은 별도 조건이며 동결 코어 실험의 결과를 덮어쓰지 않는다.

## 15. 핵심 평가 지표

### 문제 해결 능력

- 실제 S→G 완주 성공률
- 전체 최적 경로 성공률
- SPL
- 성공한 경로의 최적 길이 대비 실제 길이
- 불법 이동 실패
- 재방문·정체 실패
- 최종 정책 지도 손실
- 관찰 지도와 미관찰 지도 각각의 성공률
- 거리 난이도 Q1~Q4별 성공률

단순 평균만이 아니라 공식 미로 계열별 성능을 기록한다.

### 반복 효과

- 별도로 학습한 1회 모델 대 16회 모델
- 기록 없는 반복 대 기록 있는 반복
- 모델 내부 상태 변화량
- 기록 Attention의 입력/과거 기록 사용 비율
- 반복별 결과 진단 — 반드시 훈련 손실과 분리
- 과거 기록 교란에 따른 최종 성능 변화
- 고확신 오답 및 수렴·진동 현상

Attention 가중치의 크기만으로 사고 내용을 이해했다고 주장하지 않는다.

### 종료 효과

- 평균 종료 반복 횟수
- 종료 반복 횟수 분포
- 1회 조기 종료 비율
- 16회 강제 종료 비율
- 난이도별 종료 횟수
- 조기 종료한 문제의 실제 완주 성공률
- 고정 16회 대비 성공률/SPL 변화
- 실제 모델 추론 지연과 최대 지연
- 메모리 사용량

동일한 모델에서 고정 1·2·4·8·16회 추론을 진단으로 평가할 수 있으나, 이를 해당 횟수로 별도 학습한 모델의 대조군으로 취급하지 않는다.

GPU 배치에서는 개별 문제가 조기 종료하더라도 배치의 다른 문제가 계속 진행되어 실제 지연 감소가 예상보다 작을 수 있다.

따라서 batch=1과 대표적인 여러 배치 크기에서 지연을 별도로 측정한다.

## 16. 실제 시각화

새 실험에서 생성할 그림은 단순 최종 정확도 그래프뿐 아니라 **반복 사고의 변화를 사람이 검토할 수 있는 형태**여야 한다.

필수 그림:

1. 공식 미로와 S/G, BFS 최단 경로, 모델 예측 경로 비교
2. 1회 모델과 16회 모델의 실제 성공·실패 사례 비교
3. 기록 있는 모델과 없는 모델의 동일 문제 비교
4. 반복별 잠재 상태 변화량
5. 반복별 원본 입력/과거 기록 Attention 비중
6. 같은 문제의 기록 제거·교란 결과
7. 자율 종료 반복 수 분포
8. 난이도별 평균 반복 수와 성공률
9. 실제 정확도와 계산 비용의 관계

과거 상태를 사람이 이해하는 문장이나 명시적인 경로 탐색 단계로 강제로 번역하지 않는다.

잠재 상태 시각화는 벡터의 변화를 보여주는 진단 자료이며, 이것만으로 모델이 어떤 생각을 했는지 단정하지 않는다.

각 이미지에 공식 지도 ID, 시나리오 ID, S/G 좌표, 최적 경로 길이, 모델 경로 길이, 성공 여부, seed와 종료 시점을 포함한다.

## 17. 검증 필수 항목

본실험 전 아래 검증을 반드시 통과해야 한다.

### 데이터 및 정답

- 공식 원본 해시 일치
- 이전 EXP004 데이터 분할과 문제 ID 일치
- S/G 좌표 변형 없음

- Oracle 방향 지도 디코더의 모든 적격 문제 최적 완주
- Train/validation/test 누출 없음

### 모델 구조

- 입력 텐서 크기 일치
- 잠재 상태 `16×128` 유지
- 하나의 공유 사고 코어가 실제로 16회 호출됨
- 반복별 가중치 인스턴스 재생성 없음
- 미래 기록 참조 없음
- 원본 X 불변
- 원본 입력/기록 위치·출처 구분 가능
- 모든 Attention 모듈의 gradient 흐름
- 과거 기록을 통한 gradient 흐름
- 최종 출력부가 사고 코어로 피드백되지 않음
- 최종 손실이 중간 상태의 정답 지도 손실을 포함하지 않음

### 종료 정책

- 첫 번째 반복부터 종료 선택 가능

- 추론 중 종료 후 불필요한 코어 호출 없음
- 동결 코어의 가중치 불변
- REINFORCE 로그 확률과 실제 선택 이력 대응
- 정답을 종료 판단부 입력으로 누출하지 않음
- 강제 종료와 자율 종료 분리
- 체크포인트 복원 후 같은 정책의 결정적 추론 재현

### 보존

기존 H001, H002/SH001 EXP001~004, 공식 데이터의 전체 파일 목록과 SHA-256을 실행 전후 비교한다.

원본 체크포인트 및 이전 결과를 덮어쓰지 않는다.

각 실행의 소스 스냅샷, 설정, 데이터 해시, 모델 체크포인트, optimizer 상태, RNG 상태, 검증 결과를 보존한다.

NaN/Inf, OOM, 실험 중단, 재개 등의 상황은 자동으로 숨기거나 삭제하지 않는다.

재개 기능은 완료된 단계를 다시 학습하지 않고, 설정·데이터·소스 버전이 맞는지 확인한 뒤 동작하도록 한다.

## 18. 실행 순서와 실패 처리

전체 작업은 다음 순서로 진행한다.

**Phase 0 — 데이터 및 구조 검증**

공식 데이터 재사용, 최종 정책 라벨 생성, Oracle 디코더, 입력·잠재 상태 모양, 공유 가중치와 gradient 테스트.

**Phase 1 — 작은 집합 학습 가능성 검사**

고정된 적은 수의 공식 문제로 1회 모델과 16회 모델이 최종 정책 손실을 줄일 수 있는지 확인한다.

**Phase 2 — 정식 문제 해결 학습**

1회 Attention 모델, 16회 기록 없음, 16회 기록 있음의 3seed 학습·검증·테스트 평가.

**Phase 3 — 종료 정책 학습**

고정 16회 기준 모델을 동결하고, 종료 헤드의 학습 및 실제 계산 절약을 비교한다.

**Phase 4 — 필요할 때 별도 공동 미세조정**

동결 모델의 조기 종료 품질이 부족할 경우 별도 run에서 공동 미세조정을 검토한다. 수행 여부와 이유를 보고한다.

Phase별로 고유한 결과를 보존한다.

명백한 버그는 수정할 수 있지만, 원래 실험이 실패했다는 이유만으로 라벨·학습 목표·모델 크기·데이터를 조용히 바꿔서는 안 된다.

정식 학습의 계산량 또는 메모리가 예상보다 크면, 우선 사전 벤치마크를 통해 문제를 측정한다. 실험 설계를 바꿔야 한다면 변경 전후 조건과 이유를 남기고 다른 run으로 실행한다.

## 19. 최종 보고서

한국어로 다음 질문에 답한다.

**1. 기존 반복 출력 지도 방식과 달리 잠재 상태 방식이 실제로 학습되는가?**

**2. 별도로 학습한 1회 Attention 모델보다 16회 반복 모델이 실제 완주율에서 좋은가?**

**3. 과거 잠재 기록을 참조하는 기능이 문제 해결에 실질적으로 도움이 되는가?**

**4. 모델은 종료 시점을 학습할 수 있는가? 아니면 전부 조기 종료하거나 16회까지 기다리는가?**

**5. 정확도와 SPL을 유지하면서 실제 연산량·지연을 줄일 수 있었는가?**

**6. 관찰하지 못한 공식 지도에서도 문제를 해결하는가?**

**7. 이 결과에서 성공한 요소와 실패한 요소는 무엇이며, 다음 연구에서는 무엇을 하나만 바꿔야 하는가?**

최종 보고에는 아래 내용을 포함한다.

- 실제 실행 run ID 및 smoke 구분
- seed별·모델별 원본 성능과 평균·표본 표준편차
- 학습·검증 곡선
- 지도별·난이도별 실제 완주율
- 종료 반복 분포
- 정확도 대비 평균 연산 비용 및 실측 지연
- 대표 성공·실패 그림
- 데이터·체크포인트·기존 실험 무결성 검증
- 구현 변경 내역
- 확인된 한계와 후속 가설 후보

실험이 실패하면 그 실패 자체도 결과로 보존한다.
