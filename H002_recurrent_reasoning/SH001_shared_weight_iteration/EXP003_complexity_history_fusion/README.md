# EXP003 — 복잡도 증가와 사고 기록 통합

완전 관측 미로에서 크기·BFS 거리·분기 등 복잡도에 따라 공유 가중치 코어와 비순환 출력 MLP의 효과를 비교합니다. 반복이 필수인 문제로 목표를 바꾸지 않으며, 부분 관측·외부 입력 갱신·무한 메모리는 범위 밖입니다.

## 실행

이 EXP003 디렉터리의 PowerShell에서 실행합니다.

```powershell
$env:PYTHONNOUSERSITE='1'
& D:\anaconda3\envs\research\python.exe -u src/train_core.py
```

데이터 생성·감사 → 코어 사전학습 → 동결 → C/D/E 헤드 → A 대조군 → 테스트·기록 교란 → 독립 검증 → 그래프·한국어 보고서를 한 명령으로 수행합니다. 실행 ID는 시간과 UUID를 포함하며 기존 실행을 덮어쓰지 않습니다. `--smoke`는 작은 데이터와 2epoch를 사용하는 별도 파이프라인 검사입니다. CUDA가 없으면 빌드 정보를 포함한 오류가 나며 CPU 실행은 명시적인 `--device cpu`만 허용합니다. 사용자 패키지 혼입을 막기 위해 `PYTHONNOUSERSITE=1`을 검사합니다.

```powershell
& D:\anaconda3\envs\research\python.exe src/verify.py results/<run_id>
& D:\anaconda3\envs\research\python.exe src/analyze.py results/<run_id>

```

재검증은 `verification_recheck.json`에 남깁니다. analyze/visualize는 원래 예측을 사용해 파생 통계·그림·자동 보고서를 재생성합니다. 코어·헤드 가중치를 바꾸지 않습니다. 실패 시 `failure.json`과 가능한 학습 중간 체크포인트를 보존하며 조건을 자동 변경하거나 실패 실행을 삭제하지 않습니다.

## 모델과 비교 원칙

| 방식 | 구조 | 최종 입력/목표 |
|---|---|---|
| A | 768→256→256 | 원본 V/W/G → R_final |
| A_large | 768→1088→256 | 파라미터 규모 대응 단일 MLP |
| A_flops | 768→3328→256 | 추론 선형 FLOPs 대응 단일 MLP |
| B | 공유 코어 1024→256→256, 8회 | R8을 그대로 출력 |
| C | 동결 코어8회 + 헤드2816→256→256, 1회 | 원본 + R8을 8슬롯 복제 → R_final |
| D | C와 같은 코어·헤드 | 원본 + 실제 R1~R8 → R_final |
| E | C/D와 같은 헤드, 코어 없이1회 | 원본 + 0슬롯8개 → R_final |

코어는 ReLU/Sigmoid, 출력 헤드와 단일 A들은 ReLU/logits입니다. 코어에 `[V,W,G,R]`를 주고 R0=G로 시작합니다. 매 반복 입력의 V/W/G는 원본 그대로이며, R은 sigmoid 뒤 V로 마스킹하여 패딩을 탐색 셀로 사용하지 않습니다. 실제 예측한 R을 재사용하고 teacher forcing을 하지 않습니다. 헤드는 한 번만 호출하며 그 결과를 코어로 되돌리지 않습니다.

코어328,192개 + 헤드786,944개 = 총1,115,136개입니다. A_large는1,115,456개로0.0287% 차이입니다. A_flops는 C/D의 코어8회+헤드1회의 선형 forward 연산과 정확히 같은6,815,744 FLOPs/sample입니다. 파라미터 수도 학습 wall time도 동시에 맞춘 모델이라는 뜻은 아닙니다.

E는 0 입력 가중치에 loss gradient가 없어 기능적으로 기본 A와 같은 입력 형태를 갖습니다. C의 복제 슬롯도 가중치 합으로 축약할 수 있습니다. C/D/E의 명목 파라미터·연산량이 같아도 기능 차원까지 같다고 주장하지 않습니다. 이런 한계를 포함해 기록의 효과를 해석합니다.

## 학습과 비용

기본 seed42/123/2026, 코어80epoch·헤드80epoch·A별80epoch, AdamW lr0.001/weight_decay0.01, batch128, FP32/TF32 비활성/deterministic입니다. 지시문에 없는 epoch·optimizer 값은 기존 실험 설정을 명시적으로 이어받았습니다. 초기화는 코어 seed, 헤드/A는 seed+50000, 배치 순서는 seed+10000입니다.

각 seed의 코어는 R1~R8 BCE 평균으로 먼저 학습합니다. 모든 split의 실제 예측 기록을 만들고 코어를 동결합니다. C/D는 동일 기록을 사용하고 C/D/E 헤드는 같은 초기 state_dict와 같은 배치 순서에서 독립 학습합니다. 모델이 만든 기록과 BFS 정답은 별도 경로이며, 헤드 특징 생성 함수는 정답을 인자로 받지 않습니다. A들의 최종 목표와 데이터는 헤드들과 같습니다.

표본당 유효 셀 BCE를 평균한 뒤 배치를 평균하므로 16×16 샘플이 8×8보다 픽셀 수만으로 큰 가중치를 갖지 않습니다. 검증은 모니터링용이며 마지막 epoch를 고정 사용합니다. 테스트로 checkpoint·epoch·조건을 선택하지 않습니다. End-to-end 재학습은 하지 않습니다.

기본 학습 데이터는12,288개이므로 한 단계80epoch는7,680 optimizer step입니다. C/D는 코어7,680 + 헤드7,680 총15,360step을 사용합니다. B는 코어 단계, E는 헤드 단계만 비용을 부과합니다. 실제 실행에서 코어는 seed마다 한 번만 훈련하지만 독립 시스템 비교에서는 C/D에 코어 비용을 각각 포함합니다. 캐시 계산·압축·저장 비용과 기록 byte 수는 별도 기록합니다.

추론 시간은 캐시를 사용하지 않은 실제 전체 모델을 CUDA 동기화 포함 wall time으로 측정합니다. warm-up10회 후30회, 테스트 앞128개 고정 배치이며 평균·표준편차 및 CPU↔GPU 전송 포함 시간을 저장합니다. C/D는 코어8회·헤드1회, E는 헤드1회입니다. 선형 FLOPs는 multiply-add=2이며 활성화·mask·cat·메모리 접근·역전파·optimizer는 제외합니다. 학습 시간은 검증·gradient 기록을 포함하며 cache/test/그래프는 별도입니다. allocated peak와 측정 시작점 대비 증가량을 모두 기록합니다.

## 데이터·복잡도 감사

각 크기8/12/16별 train4096·val1024·test1024로, 전체12,288/3,072/3,072입니다. 데이터 seed42로 고정합니다. 무작위 장애물 지도와 DFS 통로의 일부 간선을 끊은 지도를 같은 수로 생성합니다. 큰 직선 장벽을 강제로 두지 않습니다. G는 열린 칸에서 선택하고 eccentricity≥4, 분리된 열린 셀≥2 및 열린 셀의8% 이상을 요구합니다. 이 제약을 만족하지 못하면 거부하고 생성 예산 초과 시 오류를 내며 조용히 완화하지 않습니다.

각 크기의 고유 지도 풀을 먼저 셔플해 분할합니다. 회전·반사로 같은 지도는 G/S나 캔버스 위치가 달라도 전체 split에서 중복을 제거합니다. 작은 지도는 캔버스 내 위치·방향이 변합니다. 유효 영역은 V=1, 패딩은 V=0/W=0/G=0, 거리=-1로 구분합니다. split·크기별 S 도달 가능/불가50:50이며 S는 모델 입력에 포함하지 않습니다.

`dataset.npz`는 problem(V/W/G), BFS distances, start, meta를 저장합니다. 거리≥0이 R_final, 0≤거리≤k가 R_k입니다. meta 열은 크기, eccentricity, 분기 수(차수≥3), 막다른 길(차수1), 열린 성분 수, 분리 비율, 벽 밀도, 평균/최대 우회 비율, 생성 계열, S 거리, cycle rank입니다. 우회 비율은 G부터 실제 최단 거리/Manhattan 거리입니다. 분기·막다른 길은 전체 유효 열린 그래프 기준입니다.

Easy4~8/Medium9~16/Hard17~32/Extreme≥33을 고정 사용합니다. 크기와 거리 난이도는 별도 축과 교차 표로 보고합니다. 해당 크기에서 생성되지 않은 구간은 n=0/N/A이며 임의 보간하지 않습니다. 분기·막다른 길·성분 수·우회 비율·계열별 평가도 CSV/JSON으로 보존합니다. 전체 빈칸 출력 기준선과 전체0 출력의 오류도 감사합니다.

## 기록 활용 검사와 그림

원래 학습된 D를 재학습하지 않고 전체 제거, R8 복제, 역순, 고정 순열, 다른 샘플 전체 기록/R4 대체, R1~R8 각각 0 대체를 평가합니다. donor는 테스트 순서를 한 칸 순환한 다른 샘플입니다. 분포 밖 입력을 만들 수 있으므로 성능 변화만으로 인간이 이해하는 활용 방식의 인과 증거라고 판단하지 않습니다.

크기/거리별 IoU·완전 해결률, 크기×난이도 D−A/A_large/A_flops/C/E 격차, 기록 교란, 품질 대비 비용 그래프를 만듭니다. 개별 샘플은 첫 seed의 D−C 최대 개선/악화·D 최저 성능·최장 경로·크기별 첫 샘플을 골라 동일 인덱스의 R1~R8, B/C/D/E/A 출력, 정답을 비교합니다. 별도 그림에서 D가 C/B/E 대비 고친 셀(초록)과 새로 틀린 셀(보라)을 구분합니다. 벽=짙은 회색, 발견 정답=초록, 오탐=빨강, 누락=노랑, 패딩=연보라, G=파란 원, S=자홍 별입니다.

## 검증·보존

데이터 seed 재생성·중복 검사와 독립 동기식 flood-fill로 모든 BFS 거리를 검증합니다. 입력/출력 차원, 공유 코어8회, 원본 context 고정, 예측 R 재입력, 모든 중간 상태 gradient, R 패딩 마스크, 동결 코어 불변, 헤드1회/피드백 없음, C/D/E 초기화·배치 순서를 검사합니다. 전 split 캐시를 코어 재출력과 정확히 대조하고, 모든 체크포인트·D 교란 출력을 복원하며 독립 FP64 torch BCE·IoU와 대조합니다.

기존 H001, H002 EXP001/EXP002, 공용 data의 전체 목록·SHA-256을 실행 전후 비교합니다. 원본8개 소스와 해시를 보존합니다. `checkpoints/<run_id>/`, `results/<run_id>/`는 기존 Git ignore 규칙을 따르며, 별도 `REPORT.md`와 이 README는 Git 관리 대상입니다.
